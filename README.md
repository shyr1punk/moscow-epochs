# Москва по эпохам

Интерактивный атлас московского реестра культурного наследия: реальные полигоны, датировки, ансамбли, районы и современные учётные кварталы.

**Сайт:** https://shyr1punk.github.io/moscow-epochs/

## Что есть

- Полный снимок набора №530: 7 016 записей (7 014 исходных идентификаторов; две пары дублей сохранены).
- 6 978 записей с полигонами, 38 с точечным расположением; поиск по всем записям.
- Поиск по названию и адресу; совместные фильтры периода, района, категории, ансамбля, квартала и прямоугольной области.
- Карточки с официальным названием, датировками, охранным статусом и номером ЕГРОКН.
- 698 подготовленных групп ансамблей и 995 кварталов, содержащих объекты реестра.
- Состояние фильтров, выбранная карточка и положение карты в URL; мобильные панели.

Это **карта датировок объектов из реестра**, не реконструкция всей Москвы на выбранный год. Полигон источника не обязательно является контуром отдельного здания.

## Запуск

Нужны Node.js 24 и npm. Python 3 и `unzip` нужны только для обновления данных.

```sh
npm ci
npm run dev
npm test
npm run data:check
npm run build
```

Локальный адрес: `http://127.0.0.1:5173/moscow-epochs/`. Публикация — GitHub Actions → GitHub Pages после push в `main`. Проверки браузера используют установленный Google Chrome:

```sh
npx playwright test
```

В автоматических сценариях запросы к тайлам OSM блокируются намеренно: тесты не скачивают подложку массово и проверяют работу без неё.

## Данные и воспроизводимость

Источники: [ОКН №530](https://data.mos.ru/opendata/530), [адресный реестр №60562](https://data.mos.ru/opendata/60562), [учётные кварталы №64068](https://data.mos.ru/opendata/64068).

`public/data/manifest.json` указывает опубликованный снимок. В его `report.json` сохранены версии источников, даты, точные адреса выгрузок, SHA-256 и статистика качества. Исходный архив ОКН, метаданные источников и связанные адресные записи находятся в `data/raw/`. Полные архивы адресов (~112 МБ) и кварталов сохранены локально при импорте и исключены из Git; точные выгрузки можно получить по `downloadUrl` из отчёта и проверить по SHA-256.

```sh
npm run data:update
npm run data:check
npm test
npm run build
# Затем проверить изменения и опубликовать отдельным commit/push.
```

Обновление получает метаданные и готовые JSON-архивы через открытый механизм экспорта самого портала (`/api/v2/odataExports/status`, `/api/v2/odata/MEDIA/getFile`). Это публичные endpoints сайта, не гарантированный стабильный API. При изменении контракта импорт завершится ошибкой; старый опубликованный снимок сохранится. Ключ API для текущих выгрузок не нужен, браузер сайта к московскому API не обращается.

Перед переключением `manifest.json` проверяется число записей и уникальность внутренних идентификаторов. Официальные повторяющиеся `global_id` получают суффикс хеша исходной записи; исходный идентификатор сохраняется в карточке. Новые снимки создаются в отдельном каталоге, старые автоматически не удаляются. Переключение манифеста атомарное. Не публикуйте каталог `data/staging`.

При наличии уже скачанных полных архивов и метаданных можно повторить подготовку без сети: `npm run data:update -- --offline`.

## Правила интерпретации

- Из официального названия извлекаются только датировки с признаками года/века. Произвольные числа не считаются годами.
- Даты после явных маркеров «здесь», «в котором», «с … г.» и связанные с биографиями/событиями исключаются. Парсер консервативный, эвристический, не заменяет экспертную проверку.
- Несколько дат не сводятся к первому числу; отдельные этапы и исходный текст сохраняются. Прямо указанные строительство, перестройка, реставрация отмечаются отдельно; иначе роль — «датировка в названии».
- Римский век превращается в интервал: XVIII — 1701–1800. Начало — первые 33 года, середина — следующие 33, конец — остальные; половины по 50 лет. Цветовые периоды условные (например, 1700–1799); пересечение нескольких периодов отображается нейтральным цветом.
- Если период записи пересекает выбранный интервал, запись остаётся видимой. Неизвестные даты включаются отдельным переключателем.
- Ансамбли: нормализованное имя и общий УНОМ/улица при расстоянии менее 2 км, либо менее 250 м в одном районе. Даты ансамбля не наследуются; одиночные и неподтверждённые связи остаются текстом.
- Квартал определяется по центру геометрии; объект на границе может относиться к нескольким кварталам. Это современное учётное деление, не историческая граница.
- Координаты проверяются на конечность, ожидаемый регион, замкнутость и ненулевую площадь колец. Полная топологическая экспертиза не выполняется. При отсутствии пригодного полигона используется связанный адресный полигон по УНОМ, иначе исходная точка. Контуры не выдумываются.

## Технологии и ограничения

React, TypeScript, Vite, MapLibre GL JS. Данные списка, геометрия, кварталы и порции карточек загружаются отдельно. Постоянного сервера, аккаунтов и аналитики нет. Обновления только ручные. При недоступности подложки остаются контуры и список; при отсутствии WebGL доступен поиск и карточки.

Подложка © OpenStreetMap contributors. Тайлы используются только для интерактивного просмотра с обычным кешированием, без офлайн-загрузки и предзагрузки города. [Правила сервиса тайлов](https://operations.osmfoundation.org/policies/tiles/). Карта требует интернет-соединения, доступность сторонней подложки не гарантирована.

В браузерах с `document.modelContext` дополнительно регистрируются три необязательных инструмента WebMCP: чтение результатов, изменение поиска, открытие карточки. В обычных браузерах интерфейс работает без этой возможности. Контракт проверен тестовым адаптером; нативная поддержка WebMCP в текущем браузере не подтверждена.
